# NutriGuard IoT (Raspberry Pi 3B+ × DHT11)

<p align="center">
  <a href="README.md">中文</a> | <strong>English</strong>
</p>

Edge gateway + optional direct on-chain script, integrated with the main repository's Flutter App and Hardhat smart contract, implementing an end-to-end demo of "automatic temperature/humidity collection → on-chain → App visualization".

---

## Directory Structure

```
nutriguard_iot/
├── sensor_test.py            # M0 hardware connectivity acceptance test
├── edge_gateway.py           # M1 edge gateway (Flask REST)
├── chain_agent.py            # M3 direct on-chain (Plan B)
├── abi/
│   └── NutriGuard.json       # Copied from Blockchain/artifacts, generated by scripts/sync_abi.ps1
├── scripts/
│   └── sync_abi.ps1          # ABI sync script from Windows dev machine → RPi
├── nutriguard-iot.service    # systemd auto-start unit
├── .env.example              # Environment variable template
├── requirements.txt
└── README.md
```

## M1 Quick Start

### 1. Pull Code on Raspberry Pi

```bash
cd ~
git clone <repo-url> nutriguard
cd nutriguard/nutriguard_iot
```

### 2. Create Virtual Environment and Install Dependencies

```bash
sudo apt install -y libgpiod-dev
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

### 3. Prepare Environment Variables

```bash
cp .env.example .env
chmod 600 .env
# Modify DEVICE_ID / DHT_GPIO as needed
```

### 4. Verify Sensor (Skip if M0 Already Complete)

```bash
python sensor_test.py
```

Expected: ≥ 80% read success rate within 30 consecutive seconds.

### 5. Start the Edge Gateway

```bash
python edge_gateway.py
```

In another terminal:

```bash
curl http://localhost:5000/health
curl http://localhost:5000/sensor/latest
```

Successful response example:

```json
{
  "device_id": "rpi-nutriguard-01",
  "timestamp": 1713312345,
  "temperature_c": 24.0,
  "humidity_pct": 57.5,
  "sample_count": 10,
  "quality": "ok"
}
```

### 6. Register as systemd Service (Auto-start on Boot)

```bash
sudo cp nutriguard-iot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now nutriguard-iot
sudo systemctl status nutriguard-iot
journalctl -u nutriguard-iot -f
```

> If you are not running as the `pi` user, or the project path is not `/home/pi/nutriguard_iot/`, update the `User` and paths in `nutriguard-iot.service` accordingly.

## Debugging on Non-RPi Environments (Mock Mode)

Windows / macOS dev machines don't have `adafruit_dht` and `board` modules, so running directly will fail.
Set `MOCK_SENSOR=1` to start with pseudo-random data, enabling parallel Flutter development:

```powershell
# PowerShell
$env:MOCK_SENSOR="1"; python edge_gateway.py
```

```bash
# Linux/macOS
MOCK_SENSOR=1 python edge_gateway.py
```

The Flutter App on a phone can access via `http://<dev-machine-LAN-IP>:5000/sensor/latest`.

## M3 Direct On-Chain (Plan B)

### 3.1 Prepare ABI

```powershell
# Windows dev machine, ensure npx hardhat compile has been run
cd D:\nutriguard\nutriguard_iot
.\scripts\sync_abi.ps1 -RpiHost pi@nutriguard-rpi.local
```

### 3.2 Configure .env

```bash
# On RPi
cd ~/nutriguard_iot
nano .env

# Key changes:
#   ETH_RPC_URL=http://<dev-machine-LAN-IP>:8545
#   CONTRACT_ADDRESS=<latest deployed contract address>
#   MERCHANT_PRIVATE_KEY=<merchant account private key>
chmod 600 .env
```

### 3.3 Manual Trigger

```bash
source .venv/bin/activate
# Arguments: productId weight_g ph_x100
python chain_agent.py 1 200 0
```

Successful output example:

```json
{
  "status": "ok",
  "tx_hash": "0xabc...",
  "block": 42,
  "temperature": 24,
  "humidity": 58,
  "weight": 200,
  "ph_value": 0,
  "device_id": "rpi-nutriguard-01",
  "sampled_at": 1713312345
}
```

### 3.4 Trigger via HTTP

If the edge gateway is running:

```bash
curl -X POST http://localhost:5000/sensor/submit/1 \
     -H "Content-Type: application/json" \
     -d '{"weight": 200, "ph": 0}'
```

**M3 Acceptance:**

- [ ] First submission for a `productId` returns `status=ok`
- [ ] Re-submitting the same `productId` returns `status=failed` with error containing `already submitted`
- [ ] When sensor is disconnected, returns `status=stale`
- [ ] After closing the Hardhat node, returns `status=failed` with error pointing to RPC connection issue

## §7 End-to-End Integration (M4)

### 7.1 Three-Service Startup Order

**1. Dev Machine (Windows PowerShell)**

```powershell
cd D:\nutriguard\Blockchain
npx hardhat node --hostname 0.0.0.0

# Open another terminal
cd D:\nutriguard\Blockchain
npx hardhat run scripts\deploy.js --network localhost
# Note the contract address and update:
#   - D:\nutriguard\nutri_guard\lib\config\app_config.dart (nutriGuardContractAddress)
#   - RPi ~/nutriguard_iot/.env (CONTRACT_ADDRESS)

# Sync ABI to RPi
cd D:\nutriguard\nutriguard_iot
.\scripts\sync_abi.ps1 -RpiHost pi@nutriguard-rpi.local
```

**2. Raspberry Pi**

```bash
sudo systemctl restart nutriguard-iot
journalctl -u nutriguard-iot -f
# In another terminal
curl http://localhost:5000/sensor/latest
```

**3. Flutter App**

```powershell
cd D:\nutriguard\nutri_guard
flutter run
# Log in with merchant account
```

### 7.3 Common Issues Quick Reference

| Symptom | Checkpoints |
|---------|------------|
| Flutter button click shows `Connection refused` | Check `curl <RPi IP>:5000/health`; verify phone and RPi are on the same subnet |
| `curl` works but App reports `Cleartext HTTP not permitted` | Verify `usesCleartextTraffic="true"` in AndroidManifest is effective; reinstall APK |
| `chain_agent.py` reports `Unable to connect to RPC node` | Check if `hardhat node` was started with `--hostname 0.0.0.0`; verify firewall allows port 8545 |
| On-chain error `Production data already submitted` | Each productId can only be submitted once per contract; restart hardhat node or create a new product |
| `estimate_gas failed` | Usually due to contract `require` failure (e.g., productId doesn't exist or product doesn't belong to this merchant) |
| `attribute 'rawTransaction' not found` | web3.py 7.x changed field to `raw_transaction`; script already handles both versions |
